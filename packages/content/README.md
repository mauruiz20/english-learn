# @english-learn/content

Static, validated learning content. No AI at runtime: everything is JSON under `data/`, checked by
Zod schemas plus corpus-wide semantic rules. CI fails on malformed content (`pnpm validate:content`).

## Layout

```
src/corpus/    createCorpus: merged corpus + lookup maps (no Zod)
src/generated/ corpus.ts generated by build:corpus (committed)
src/schema/    Zod schemas and inferred types (Level, Source, Item, Exercise, Passage, Lesson, PlacementQuestion, Card, PracticeCollection, Dialogue, ContentFile)
src/validate/  Pure semantic rules; each returns { file, path, message }[] and never throws
scripts/       validate.ts CLI: main(dir) => errors; build-corpus.ts generator
data/          a1/ a2/ b1/ b2/ c1/ placement/ glossary/ practice/ — many small ContentFile JSON files (never one giant file)
```

Every file lives under `data/<a1|a2|b1|b2|c1|placement|glossary|practice>/` (subdirectories are fine).
A level directory may also hold `level.json`, the level's intro (see [Intros](#intros)). Files at the
root of `data/` or in any other directory are errors. Study cards live directly in their level
directory, in the file of their topic: `data/<level>/grammar.json`, `phrasal-verbs.json`,
`vocabulary.json` (see [Study cards](#study-cards-fichas)). Free practice lives in
`data/practice/<collection>/` (see [Práctica libre](#práctica-libre)).

## Study cards ("Fichas")

A card explains one point and links it to SRS items and practice exercises. The app shows the card
and lets the learner practice its exercises; the items it lists enter spaced repetition like any
other item.

| `kind`          | `topic`         | Extra fields                                                       |
| --------------- | --------------- | ------------------------------------------------------------------ |
| `grammar`       | `grammar`       | —                                                                  |
| `phrasal_verbs` | `phrasal-verbs` | `entries` (3–6): `{ verb, es, separable, example: { en, es } }`    |
| `vocabulary`    | `vocabulary`    | optional `collocations` (1–8 `{ en, es }`), optional `falseFriend` |

Every card has `id` (`<level>.<topic>.<slug>`), `level`, `topic` (fixed by `kind`), `kind`,
`title` (Spanish, short), `summary` (Spanish, 1–2 sentences), `form` (the pattern, e.g.
`look forward to + verbo-ing`), `uses` (1–4 Spanish bullets), `pitfalls` (0–4
`{ wrong, right, why }`: English mistake typical of Spanish speakers, its correction, and a Spanish
explanation), `examples` (4–8 `{ en, es }`), `itemIds` (≥ 1) and `exerciseIds` (6–8). A
`falseFriend` is `{ en, looksLike, actually }` (`actually` / `actualmente` / `en realidad`).

- **Items**: each grammar point, phrasal verb or word the card teaches is one item with the card
  topic among its `topics`. A card may reuse an existing item at or below its level (e.g.
  `b1.travel.check-in` gets the extra topic `phrasal-verbs`) instead of creating a duplicate.
  When a card teaches one item, the item id usually equals the card id (ids are unique per
  entity kind, so this is allowed).
- **Exercises**: the existing exercise types, with the card level and the card topic segment
  (`b1.grammar.look-forward-to-cloze-1`). Every item an exercise practices belongs to the card,
  every card item is practiced by at least one card exercise, and an exercise belongs to one card
  only. Card exercises are not part of lessons.
- Card topic files hold `cards`, their new `items` and their `exercises`; they need no passages
  or lessons. The Spanish labels for the card topics belong to the app (like the other topic
  labels): `grammar` → _Gramática_, `phrasal-verbs` → _Phrasal verbs_, `vocabulary` →
  _Vocabulario_.

## IDs are immutable

Ids look like `<level>.<topic>.<slug>` (e.g. `b1.travel.although`, `b1.travel.cloze-001`);
placement questions use `placement.<level>.<slug>`. **Once published, an id must never change or be
reused**: learner progress references items and exercises by id. To retire content, remove it from
lessons but keep the id reserved; to change meaning, add a new id.

## Authoring conventions

- **Data order carries no meaning.** The app shuffles answer options and word-order tokens at
  render time (the shuffle lives in `@english-learn/domain`), and grades by content, not position.
  Still, author `answerIndex` at varied positions and scramble `tokens`, so the data never leaks
  the answer if a client forgets to shuffle.
- **American English** spelling throughout (`traveled`, `canceled`, `color`, `center`).
- **Text fields** are non-empty and have no leading or trailing whitespace, and never double the
  final period (`8 p.m.`, not `8 p.m..`). A three-dot ellipsis (`where is...?`) is fine.
- **`accepted` lists** (translate_write) are **answer patterns** that should cover every natural
  way a learner may write the sentence: numerals vs words (`{11|eleven}`), synonyms at level
  (`{Although|Even though|Though}`), word order of adverbs and time phrases, optional politeness
  and fillers (`[please]`), will / going to where both are natural, and common rephrasings
  (`we {arrived|got there} on time`). Contractions (`I'm` / `I am`), case and final punctuation are
  handled by the matcher, so do not spell them out. Every expansion must be correct English and a
  correct translation. The first sentence of the first entry is the reference answer shown after
  a wrong answer, so make it the most natural one.

  | Syntax      | Meaning                                                 |
  | ----------- | ------------------------------------------------------- |
  | `{a\|b\|c}` | exactly one alternative; one may be empty (`{very \|}`) |
  | `[x]`       | optional; `[a\|b]` = nothing or one of them             |
  | nesting     | `I get up {early\|at six[ o'clock]}.`                   |
  | `\{` `\[` … | a literal `{ } [ ] \| \`                                |

  Spaces are normalized in every expansion (no double spaces, none before `.,!?;:`), so write
  `I [really ]like it.` or `I like it [very much] .`. An exercise may stand for at most 2,000
  sentences. Patterns stay compact in the generated corpus; the app expands them once per
  exercise when grading. Learners can mark an answer as "also correct" (`answer_disputed`
  events); `disputed-answers` lists them by exercise from a JSON export of events (an array, or
  `{ "events": [...] }`), marking those the current patterns already accept, to grow the patterns.

- JSON files must not repeat a key in the same object (`JSON.parse` would silently keep the last).

## Semantic rules

Text comparisons use `normalize`: Unicode NFC, curly quotes to straight quotes, lower-case, trimmed,
inner whitespace collapsed, trailing `.,!?;:` stripped. So `"aunque"` and `"aunque."` are duplicates.

Reference-free rules (run on every file that parsed, even when other files fail):

1. Layout: see above; `placement/` holds only `placement` entries and level directories never hold
   them; `glossary/` holds only `glossary` entries and no other directory holds them; every entity
   under `<level>/` has that level; an id's level prefix matches its `level`.
2. `answerIndex` is within `options` (vocab, translation_choice, reading questions, placement).
3. Options have no normalized duplicates.
4. Cloze: the sentence has exactly one underscore run and it is exactly `___`; answers and
   distractors contain no `_`; at least 2 distractors; no normalized duplicates among answers or
   among distractors; no answer appears among the distractors.
5. Word order: see the convention below.
6. No duplicates inside one entity: `lesson.exerciseIds`, `exercise.itemIds` (exact), `topics`,
   word-order `accepted` (normalized).
7. Topics: `item.topics` / `passage.topics` include the topic segment of their id; a lesson's id
   topic segment equals `lesson.topic`; every exercise a lesson lists has that topic segment.
8. Punctuation: no text field contains exactly two dots in a row (`..`, e.g. `p.m..`) or four or
   more; a three-dot ellipsis `...` and `…` are allowed. Register: Spanish is neutral, with tú
   ("puedes", "inicia"), never voseo ("podés", "iniciá", "usalo", "vos"); `findVoseo`
   (`src/validate/voseo.ts`) catches the common shapes, allowing "pedí" / "abrí" as the first
   person past. The app's copy is checked with the same function (`apps/mobile/src/neutral-spanish.test.ts`).
9. Glossary entries (see [Glossary](#glossary)): file name, order, form shape, headword among the
   forms, word vs phrase forms.
10. Answer patterns (translate_write `accepted`): every entry parses; each entry and the whole
    exercise stand for at most 2,000 sentences; no sentence (normalized) comes from two entries;
    every sentence is non-empty and has no doubled terminal punctuation. Glossary coverage
    (rule 16) checks every sentence a pattern stands for.

Cross-file rules (run only when every file parsed and passed the schema):

11. Ids are unique per entity kind across the whole corpus.
12. References resolve: `exercise.itemIds` -> items, `reading.passageId` -> passages,
    `lesson.exerciseIds` -> exercises.
13. Exercise topic: the topic segment of an exercise id is a topic of at least one item it
    references. (Chosen over "equals the lesson topic" because it holds for exercises outside any
    lesson too; together with rule 7 it keeps lesson, exercise and item topics aligned.)
14. Levels: an exercise has its lesson's level; a reading exercise has its passage's level; every
    item an exercise references is at or below the exercise level (A1 < A2 < B1 < B2 < C1).
15. Glossary ids are unique, and a form belongs to at most one entry across the whole glossary.
16. Glossary coverage: every word of learner-visible English text resolves to a glossary entry.

Card rules ([Study cards](#study-cards-fichas)); the layout (rule 1) and unique ids (rule 11) also
cover cards, and cards can never sit in `placement/` or `glossary/`:

17. Cards, reference-free: the id topic segment is the card `topic`; a card lives in
    `<level>/<topic>.json`; a pitfall's `wrong` and `right` differ (normalized); no duplicates
    inside a card (uses, example sentences, phrasal verbs and collocations normalized; item and
    exercise ids exact).
18. Cards, cross-file: `itemIds` and `exerciseIds` resolve; every exercise has the card level and
    topic segment; every item is at or below the card level and has the card topic; every item an
    exercise practices is in the card, and every card item is practiced by a card exercise; an
    exercise belongs to at most one card.

Lesson rules (cross-file):

19. New items (`lesson.newItemIds`, see [Lessons](#lessons)): no duplicates, and every id is an
    item that an exercise of the lesson practices.
20. Reviewable lesson items: every item a lesson practices is also practiced by at least one
    non-reading exercise somewhere in the corpus. The daily review never picks a reading (too
    long for a quick review), so an item only a reading covers would get a review state from the
    lesson and never come back. Such items get a short review-only exercise (usually `vocab`)
    that sits in no lesson (e.g. `a2.weather.vocab-004` for `windy`).
21. Linked cards (`lesson.deepenCardIds`): no duplicates, every id is a card, and every card is
    at or below the lesson level.
22. One link per topic: a card is linked by at most one lesson of a topic (same level and
    `topic`), the lesson that teaches it, so the path never shows the same "Profundiza" card under
    two lessons of a topic. Lessons of other topics may still link it when they teach it too
    (`a2.grammar.have-to` deepens both `a2.home.lesson-002` and `a2.work.lesson-002`).
    Practice lessons are not on the path, so the rule skips them.

Practice rules ([Práctica libre](#práctica-libre)):

23. Practice, per file: a collection `practice.<slug>` lives in `practice/<slug>/`, its group ids
    start with `practice.<slug>.`, a group never lists a lesson twice; `practice/` holds no cards
    or placement entries, and collections live nowhere else.
24. Practice, cross-file: collection and group ids are unique; every group lesson is a lesson of
    its collection's directory at the group's level, and every lesson there is in exactly one
    group; no practice lesson practices an item a path lesson practices, and no practice item
    repeats a path item's term (without its parenthesized part) under another id, so practice
    never changes path progress; no lesson id is also a card id (results are kept by id).

Intro rules ([Intros](#intros)):

27. Intros, per file: a lesson intro's mistake has different `wrong` and `right` (normalized); a
    level intro lives in its own level's `level.json` (`a2/level.json` holds `"level": "A2"`).
    Counts and lengths are the schema's; voseo (rule 8) and glossary coverage (rule 16) check
    intros like any other text.

Dialogue rules ([Diálogos](#diálogos)):

25. Dialogues, per file: the id is `<level>.dialogues.<slug>` and its level prefix matches
    `level`; dialogues live in `practice/<collection>/` only; character and node ids are unique;
    the start, every speaker and every `next` / `wrongNext` resolve (no dead ends); every node is
    reachable from the start; there are no cycles (every path ends); a choose turn has a good
    reply and never repeats a reply (normalized); good replies alone (and correct writing) reach
    an end; every path asks the same number of learner turns, 5 to 8; there are choose and write
    turns; at least 2 turns branch (their replies lead to different nodes); write `accepted`
    entries follow rule 10. Every string is checked for voseo (rule 8) and the English (NPC
    lines, replies, every accepted sentence) for glossary coverage (rule 16).
26. Dialogues, cross-file: ids are unique and never a lesson or card id (results are kept by
    id); turn `itemIds` and `cardIds` resolve, at or below the dialogue level; no turn practices
    an item a path lesson practices; a dialogue group lists dialogues of its collection's
    directory at the group's level, and every dialogue is in exactly one group.

### Word-order convention

Tokens are written exactly as they appear in the sentence, punctuation attached to its word
(`"rained."`). Splitting **every** accepted sentence on whitespace must give the same multiset of
tokens, so the tokens joined by single spaces in the right order rebuild each accepted sentence
exactly. Tokens must not already be in the order of any accepted sentence (pre-solved puzzle).
Both comparisons ignore case, like the app's grader, so a lowercase `usually` token can build
`Usually I wake up at six.`.

### Placement questions

A placement question carries its own `id` and `level`, so its embedded exercise (vocab, cloze or
translation_choice) omits `id`, `itemIds` and `level` but keeps `source`.

## Glossary

Static English → Spanish lookup for hover (web) / tap (mobile). Tokenizing and matching live in
`@english-learn/domain` (`annotateText`); this package holds the data and checks it.

```json
{
  "id": "glossary.traffic-jam",
  "headword": "traffic jam",
  "kind": "phrase",
  "forms": ["traffic jam", "traffic jams"],
  "senses": [{ "es": "embotellamiento, atasco", "pos": "noun" }]
}
```

- **Files**: `data/glossary/<letter>.json`, one per first letter of the headword (accents ignored),
  entries sorted by headword. Ids are `glossary.<slug>`; like content ids they never change.
- **Forms**: every lowercase surface form that should link to the entry, with straight apostrophes:
  the headword, inflections (`move`, `moves`, `moved`, `moving`), plurals, comparatives and
  contractions (`won't`, `i'm`). A form belongs to **one** entry only: homographs share one entry
  with several senses (`left`: _salió_ / _izquierda_). `word` entries have one-word forms
  (hyphenated `part-time` and dotted `p.m.` count as one word); `phrase` entries have multi-word
  forms (`get up`, `got up`, `show me around`). Phrases win over single words, longest first.
- **Senses**: 1–3, the sense the content uses most first; short, natural, neutral Latin American
  Spanish. `pos` is optional (`noun`, `verb`, `adjective`, `phrasal verb`, `expression`, …).
  Proper names get an entry too (`June` → _junio_, `Carlos` → _(nombre propio)_).
- **Coverage** (rule 16): checked texts are item terms; vocab prompts (the quoted Spanish term of a
  `Choose the English for '…'.` prompt is skipped; options are Spanish); cloze sentences, answers
  and distractors; word-order tokens and accepted sentences; translation_choice sentences; reading
  question prompts and options; translate_write accepted answers (shown as corrections); passage
  titles and texts; placement exercises; translate_write accepted answers are checked as every sentence their patterns
  stand for. Cards: pitfall `right` sentences, example `en` sentences, phrasal verbs and their
  example `en`, collocation `en` and the false friend's `en`. Lesson intros: example `en` and the
  mistake's `right` (its `wrong`, like a pitfall's, is skipped). A pitfall's `wrong` sentence is
  skipped: its deliberate mistakes (`lended`, `rised`) must never become glossary forms. A possessive (`Ana's`) resolves to its base form when it
  is not itself a form. Forms no text uses are allowed; `validate` prints their count as a warning.
- **Authoring**: `pnpm --filter @english-learn/content glossary:gaps [--limit N]` lists uncovered
  words, most frequent first, with one example text each.

## Lessons

A lesson is `{ id, level, topic, title, exerciseIds (≥ 5), newItemIds?, deepenCardIds?, intro? }`
(`intro`: see [Intros](#intros)).

- `newItemIds` (optional, 3 to 5 item ids): what the lesson introduces, shown in the app's
  end-of-lesson recap "Lo nuevo de hoy" (each one linked to its study card when a card teaches
  it, otherwise with its Spanish meaning and an example taken from the lesson's exercises).
  Pick the words, phrases and structures the lesson is about, in exercise order: items no earlier
  lesson of the course practices, study-card items and grammar first. A second lesson of a topic
  that introduces fewer than three items completes the list with the items it practices most.
  Every bundled lesson lists them; without the field the app derives them (the lesson's items
  that no earlier lesson practices, at most five).

- `deepenCardIds` (optional, 1 to 3 card ids): the study cards that really go deeper into what
  the lesson teaches, each at or below the lesson level (rule 21). The app shows them under the
  completed lesson on the path ("Profundiza") and links the recap items they teach to them: a
  recap item opens a linked card that lists it, or that teaches its term or headword (its glossary
  entry), even when the card uses another item id (`b1.culture-and-entertainment.look-forward` and
  `b1.grammar.look-forward-to`). The link is explicit: terms are never matched against cards the
  lesson does not link. Link a card only when it explains the lesson's own grammar or words, not a
  loosely related topic. Within a topic a card goes to one lesson only (rule 22): the lesson whose
  new items introduce what the card explains; when both lessons introduce part of it, the one that
  practices it most (the earlier one on a tie). City life links `b1.grammar.future-forms` to
  "Planes para el futuro" (`will`, `going to` and the present continuous), not to "La vida en la
  ciudad", which only uses `going to` once.

- Item `example` (optional, `{ en, es }`): an English sentence that uses the item and its
  Spanish. The recap shows it; without it, it takes a sentence (with its Spanish) from an
  exercise that practices the item and links the item's glossary entry. Recap items with no such
  exercise sentence carry one; its `en` counts for glossary coverage.

## Intros

**Lesson intro** (`lesson.intro`, optional): the short theory screen the app shows before the
first exercise ("Antes de empezar"), 30 to 60 seconds of reading.

```ts
intro?: {
  points: string[]; // 2–4 short bullets in neutral Spanish, each ≤ 140 chars, English in «»
  examples: { en: string; es: string }[]; // 1–2 examples
  mistake?: { wrong: string; right: string; note: string }; // note in Spanish, ≤ 120 chars
}
```

- Focus on what the lesson teaches (its `newItemIds` and exercises): the rule, the form, one or
  two short examples built from the lesson's own sentences, and the mistake Spanish speakers
  really make (`I have nine years.` → `I'm nine years old.`). No new vocabulary.
- Without `intro` the app derives one from the lesson's first linked card (`deepenCardIds`): its
  first uses, first example and first pitfall. Lessons with neither show no intro.
- Practice lessons and dialogues need none.
- **Coverage**: `src/validate/intro-coverage.test.ts` requires an intro on every path lesson of
  every level (A1 to C1) and a `level.json` for each.

**Level intro** (`data/<level>/level.json`, a bare object, not a content file):

```ts
{ level: "A1", title: string, canDo: string[] /* 3–5 "Al terminar podrás…" bullets */, topics: string[] }
```

All Spanish. The app shows it once per device, the first time the path shows the level.
Validation and the generated corpus load it as `{ levelIntro }`; `createCorpus` lists them in
`levelIntros` / `levelIntrosByLevel`.

## Práctica libre

Free practice, outside the learning path and its levels: the learner picks any topic and works
through it. A **collection** (`Phrasal verbs`) has **groups** (`Viajes`), each with 2 or 3
lessons; nothing is locked and the group's level is only a label.

```
data/practice/phrasal-verbs/collection.json   { "practice": [ collection ] }
data/practice/phrasal-verbs/travel.json       the group's items, exercises and lessons
```

- **Collection** `{ id: "practice.<slug>", title, summary, groups }`; **group**
  `{ id: "practice.<slug>.<group>", level, title, summary, lessonIds (2–3) }`. Titles and
  summaries are Spanish (a collection title may be the English name of the topic).
- **Lessons** are ordinary lessons (schema, exercise types, `newItemIds`, `deepenCardIds`) with
  the group's level, kept apart from the path's: `createCorpus` lists the lessons some group
  lists as `practiceLessons` / `practiceLessonsById`, and `lessons` / `lessonsById` keep the
  path's only. So home, the path's level logic, the album and the transfer preview never count
  them. Their items and exercises are ordinary corpus entities: the daily review brings practice
  items back like any other.
- **Separate from the path** (rule 24): practice lessons never practice a path item, so "a lesson
  is done once its items have a state" cannot change for a path lesson. Practice may reuse study
  card items (`b1.phrasal-verbs.put-off`) and link the card with `deepenCardIds`.
- **Phrasal verbs** (`practice/phrasal-verbs/`): ten groups of six verbs (A2: casa, viajes; B1:
  teléfono, dinero, relaciones, salud, estudio, tecnología; B2: trabajo, planes). Ids:
  items `<level>.phrasal-verbs.<verb>` with the object's place in the term
  (`clean (something) up`, `look up to (someone)`, `lie down`), lessons
  `<level>.phrasal-verbs.practice-<group>-<1|2|3>`, exercises
  `<level>.phrasal-verbs.practice-<group>-<type>-<n>`. Lesson 1 introduces the verbs ("conócelos"),
  lesson 2 practices them with every exercise type but reading ("practícalos"), lesson 3
  contrasts near-synonyms, particles and the object's place ("no los confundas").
- **Tiempos verbales** (`practice/tenses/`, topic `tenses`): ten groups of six items, one or
  two tenses each (A2: presente simple y continuo; B1: pasado simple y continuo, presente
  perfecto, presente perfecto o pasado, presente perfecto continuo, pasado perfecto, formas del
  futuro, verbos de estado; B2: futuro continuo y perfecto, used to y would). Form, use, time
  expressions and the typical mistakes (`I am living here since 2019`). Lessons "conócelo(s)",
  "practícalo(s)", "no lo(s) confundas".
- **Situaciones** (`practice/situations/`, topic `situations`): twelve groups of six phrases
  (A2: aeropuerto, hotel, restaurante, médico, indicaciones; B1: compras y devoluciones,
  alquilar, charla informal, llamadas; B2: quejas, entrevista de trabajo, reuniones y correos).
  Each lesson 1 has a reading with a short dialogue (speaker labels inline, no line breaks).
  Lessons "frases clave", "practícalas" and "dilo bien" (register: polite vs casual, calques and
  false friends).
- **Gramática** (`practice/grammar/`, topic `grammar`): twelve groups of six items (A2:
  artículos, preposiciones, contables e incontables, comparativos; B1: obligación y consejo,
  gerundio o infinitivo, pasiva, estilo indirecto, oraciones de relativo, preguntas y question
  tags; B2: deducciones, condicionales). Item ids start with the group
  (`a2.grammar.articles-…`) so they never clash with study-card items; the cards that already
  explain a point are linked with `deepenCardIds` instead of re-explaining it.
- In every collection, item ids are `<level>.<topic>.<slug>`, lessons
  `<level>.<topic>.practice-<group>-<1|2|3>` and exercises
  `<level>.<topic>.practice-<group>-<type>-<n>`. A new collection is content only: a new
  `data/practice/<slug>/` directory. The app lists collections (in path order of their
  directories) and groups from the corpus.

### Diálogos

Branching conversations (`practice/dialogues/`, collection `practice.dialogues`): the other
character speaks and the learner replies by choosing or by writing. A dialogue group lists
`dialogueIds` (1–6) instead of `lessonIds`; files hold `{ "dialogues": [...] }`.

```json
{
  "id": "a2.dialogues.airport-check-in",
  "level": "A2",
  "title": "Facturar en el aeropuerto",
  "setting": "Estás en el mostrador de la aerolínea con una maleta grande.",
  "characters": [{ "id": "agent", "name": "Agente", "role": "agente de la aerolínea" }],
  "start": "n1",
  "nodes": [
    { "id": "n1", "kind": "npc", "speaker": "agent", "en": "…", "es": "…", "next": "t1" },
    {
      "id": "t1",
      "kind": "choose",
      "itemIds": ["a2.situations.check-a-bag"],
      "options": [
        { "en": "…", "rating": "good", "feedback": "…", "next": "n2" },
        { "en": "…", "rating": "wrong", "feedback": "…", "next": "n2-rude" }
      ]
    },
    {
      "id": "t2",
      "kind": "write",
      "prompt": "Pide un asiento de pasillo.",
      "accepted": ["…"],
      "tip": "…",
      "next": "n3",
      "wrongNext": "n3-confused"
    },
    { "id": "end", "kind": "end", "text": "Tienes tu tarjeta de embarque." }
  ],
  "cardIds": ["a2.grammar.some-any"]
}
```

- **Nodes**: `npc` (an English line, its Spanish gloss shown on demand, the `speaker` and the
  `next` node); `choose` (2–4 replies rated `good`, `ok` — understood, but blunt or unnatural —
  or `wrong` — rude, off-topic or a misunderstanding — each with Spanish `feedback` and its own
  `next`); `write` (a Spanish `prompt`, `accepted` answer patterns, an optional Spanish `tip`,
  `next` for a right or almost-right reply and an optional `wrongNext` for a wrong one); `end`
  (a Spanish line about how it ended). Replies lead to different NPC reactions (a polite reply
  vs a blunt one) that join the main line again, so every path asks the same number of turns
  (rule 25) and "6/6" means the same on every branch.
- **Items and cards**: a learner turn may list the `itemIds` it practices (existing practice
  items, e.g. the Situaciones phrases; never path items), graded by that reply for spaced
  repetition; `cardIds` (1–3) are study cards the recap links. Dialogues create no items, so
  rule 24's terms rule holds as is.
- **Results**: the app saves a played dialogue as a lesson whose `lessonId` is the dialogue id
  (`session_completed` kind `lesson`), so its best result and the once-per-id completion bonus
  work like a practice lesson's.
- Every reply that is not `good` is clearly worse for a reason the feedback names; the app
  shows the turn's first good reply after it ("Mejor: …").
- **Bundled**: 25 dialogues in seven groups, building on the Situaciones themes. A1 "Primeros
  pasos": `introducing-yourself`, `buying-coffee`, `time-and-day` (very short lines, Spanish
  prompts and tips); A2 "Fuera de casa": `airport-check-in`, `restaurant-order` (the server
  brings the wrong dish), `doctor-visit`, `asking-directions`; A2 "Compras y recados":
  `supermarket-checkout`, `booking-a-table`, `at-the-pharmacy`; B1 "Del día a día":
  `returning-headphones`, `coworker-small-talk`, `reschedule-appointment`; B1 "Resolver cosas":
  `market-bargaining`, `splitting-the-bill` (two friends), `internet-support`, `noisy-neighbor`;
  B2 "Con tacto": `job-interview`, `hotel-complaint`, `meeting-disagreement` (two characters),
  `billing-dispute`, `giving-feedback`, `car-rental` (accepting the upsell leads to its own
  ending); C1 "Mucho en juego": `salary-negotiation`, `defending-a-decision` (two characters).
  Each has 5–7 learner turns.

## App delivery (generated corpus)

The app ships the corpus inside its bundle (offline, no filesystem access). `pnpm build:corpus`
validates `data/` and writes `src/generated/corpus.ts`: one static `import` per JSON file, sorted
by path so the output is deterministic, passed to `createCorpus`, which merges the files and adds
lookup maps (`itemsById`, `exercisesById`, `passagesById`, `lessonsById`, `cardsById`,
`glossaryById`; `cards` holds the study cards in file order) plus
`glossaryIndex`, the prebuilt lookup for `annotateText` from `@english-learn/domain` (which has no
dependencies, so the app path stays Zod-free).

- **Commit the generated file.** `pnpm corpus:check` (part of `pnpm check` and CI) fails when it is
  stale; fix it with `pnpm --filter @english-learn/content build:corpus`.
- `import { corpus } from "@english-learn/content"` works everywhere, but the package entry also
  exports the Zod schemas. The app imports `@english-learn/content/corpus`, which only carries data
  and type-only imports, so Zod stays out of the app bundle. Validation runs in CI, not on device.

## Commands

```
pnpm --filter @english-learn/content test          # unit + integration tests
pnpm validate:content                              # validate data/ (exit 1 on errors)
pnpm --filter @english-learn/content build:corpus  # regenerate src/generated/corpus.ts
pnpm corpus:check                                  # fail if the generated corpus is stale
pnpm --filter @english-learn/content glossary:gaps # words with no glossary entry
pnpm --filter @english-learn/content disputed-answers [events.json]  # disputed answers by exercise (file or stdin)
```

## Authoring

- One file per topic and level (`data/a2/food.json`; A1 files carry an order prefix, see
  [Level coverage](#level-coverage)); placement questions live in one file per level
  (`data/placement/a1.json` … `c1.json`).
- Each topic teaches 8–15 items (a B2 file holds fewer, because its lessons also practice the B2
  card items), has at least one passage, and lessons of 6–8 exercises that together cover all six
  exercise types. Lesson titles are in Spanish; Spanish text is neutral (no voseo).
- Example sentences can come from Tatoeba via `tools/content-pipeline` (see its README): run
  `download`, then `candidates --level A2`, pick sentences from `.cache/candidates-a2.json`, and
  run `verify` to check that every Tatoeba attribution quotes the English sentence exactly. Spanish
  options and prompts are our own translations; only the English sentence carries the attribution.
- Clozes must have a single correct fit among the shown choices: avoid distractors that are also
  grammatical (e.g. `got` next to `gets` in a habitual sentence).
